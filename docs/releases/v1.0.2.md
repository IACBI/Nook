Reliability release with a memory-safety fix for AMD systems. Upgrading is strongly recommended, especially on AMD graphics.

**Fixed**

- On AMD GPUs, every temperature and clock reading wrote past the end of a buffer inside Nook. The driver's performance-status structure has eighteen fields and Nook declared eight. The layout now matches AMD's SDK, and Nook refuses to call the driver at all if the two sizes ever disagree.
- GPU adapters are enumerated through DXGI again. A wrong method index meant enumeration never worked, so the list depended on a fallback that only saw adapters already reporting memory use.
- Adapter load now matches Task Manager. Usage from every process on an engine is added together and the busiest engine is shown. Before, it was the single busiest process, which under-reported shared load.
- The overlay opens where you left it. Its saved position was discarded on every launch.
- Exiting from the tray menu no longer switches off "Close button minimizes to system tray". If you exited that way before, turn the option back on once in Settings.
- The selected GPU survives a restart. Windows assigns adapter IDs per boot, so Nook now falls back to the adapter's name.
- A missing GPU engine counter no longer blanks the memory readings.

**Settings and diagnostics**

- Settings are saved a moment after each change instead of only on exit. They are written through a temporary file, so a crash or power loss can no longer leave a half-written profile.
- A field Nook cannot read now falls back to its default without resetting the others. A file that is not valid JSON is kept as `settings.bad.json`.
- Problems are recorded in `%LocalAppData%\Nook\nook.log`, which rolls at 1 MB. Please attach it to bug reports. Unexpected errors are logged with line numbers, and Nook keeps running.
- The Settings page shows the hotkeys actually configured and marks any that another application already holds.
- If Windows GPU counters are not ready yet when Nook starts with Windows, it keeps retrying.

**Notes**

The AMD fix is verified against AMD's published SDK header and a size test, not on AMD hardware. Feedback from AMD users is welcome.

The executable is still not code-signed, so SmartScreen will ask for a confirmation the first time you run it.
