Responsiveness release. A graphics driver that stops answering no longer freezes Nook. Upgrading is recommended.

**Fixed**

- Nook used to read the GPU counters and the NVIDIA/AMD driver on its window thread. When a driver hung, the window, the overlay, the hotkeys and the tray menu froze with it, for example during a driver reset, a driver update or resume from sleep. All of that reading now happens on a separate background thread, and the window stays responsive whatever the driver does.
- If the driver does not answer for three seconds, Nook clears the readings and says "The GPU driver is not responding". Readings come back by themselves when it answers again.
- Exiting Nook while a driver is stuck takes at most two seconds.
- A single failed reading no longer stops monitoring of the selected process or resets its peak and average.

**Diagnostics**

- `%LocalAppData%\Nook\nook.log` records when the driver stops and starts answering again, and any reading that takes longer than a quarter of a second.

**Verifying the download**

`Nook.exe` is built and attested by this repository's GitHub Actions workflow:

```
gh attestation verify Nook.exe -R IACBI/Nook
```

**Notes**

The behaviour during a hang was tested by stalling Nook's own driver calls on purpose, not with a real driver fault.

The executable is still not code-signed, so SmartScreen will ask for a confirmation the first time you run it.
